# 工厂级建模：统一基准、组件制造与空间装配

适用于厂房、车间、仓储或多设备产线。核心方法是：**总图自上而下给出约束，资产自下而上独立制作与复用，再回到总图验证装配。** 既有单组件质量要求继续适用；此流程不要求切换到参数化 CAD，也不把 Blender 父子链称为 CAD 配合求解器。

## 1. 先读懂总图并给出可看的基线

对 DWG/DXF、PDF 或图片先确认：目标区域、图纸版本、二维布局/立面/三视图/三维实体的区别，设备标签、块、图层、标注及外部引用是否可读。块定义可能未被插入，不能把定义数当现场数量。

- 尽早给用户可读的全图和关键区放大预览。原软件截图、转换后重绘、模型投影分别标明；不要把重绘预览当原生 CAD 渲染。
- 只读保留原文件。转换在工作副本进行；记录工具、错误及图形覆盖范围。文件存在或体积较大不证明转换完整，要检查结构结束、解析结果、关键图形/文字和区域数量。
- 转换警告涉及不支持的实体、外部引用或不完整数据时，先判断受影响内容。不能因为解析器报错就批量删除未知代理对象；只有明确属于非图形元数据且图形已独立保留时，才可从分析副本过滤，并保留原始转换副本与记录。
- 平面图中的矩形可能是功能区、设备基础、工位分配或实体外形。结合标签、图层、重复方式与图块结构分类；证据不足时保留待定解释，不把分区挤出成一台机柜。
- 厂房边界保留原有斜边、非正交关系和开口。用包围盒代替轮廓、闭合线段间隙或补缺边，都属于推导，需记录依据和误差范围。

## 2. 建立全项目共同基准

分派组件前记录下表；用户已有约定则沿用。默认按实际尺寸 1:1 建模，工作单位可按下游选择，通常用米制场景统一管理。

| 项目 | 需要明确的内容 |
|---|---|
| 单位与比例 | 来源单位、建模单位、每 Blender 单位对应的实际长度、导入导出的换算 |
| 坐标与原点 | 右/左手约定、上轴、厂区坐标方向、原图到场景的可逆变换、地面标高 |
| 组件安装基准 | 每类组件原点、局部前方、安装面、接口坐标；不要求所有对象都以几何中心为原点 |
| 空间约束 | 已知安装点/朝向、设备本体占地、分配区域、接口高度、运动与检修空间；未知项单列 |
| 外观与用途 | 整厂和近景观察距离、哪些组件需操作、统一材质命名与表面处理、细节预算 |
| 文件与所有权 | 组件 ID/版本、独立输出位置、总装负责者、实时 Blender 写入负责人 |

单位不可仅看文件头或界面显示。切换单位显示或 Unit Scale 不会自动把既有网格改成正确尺寸，仿真和导出换算还需各自验证。优先用带单位的尺寸/图注、制造商尺寸和图块换算交叉核对；同时核查尺寸样式的测量倍率（如 DIMLFAC）、文字覆盖与块的实际单位，避免把手写标注当测量值。两条纯数字标注与几何长度的比值接近 1 不能独立证明物理单位。存在冲突时找不同方向或独立对象的尺度锚点；无法确认且会实质改变组件/接口时集中澄清，期间继续分类与不依赖绝对尺度的工作。比较对象须语义一致，不能用建筑规划面积校准设备尺寸。圆整标注与实际线条略有差异时说明采用哪个依据，不强制拉伸所有几何凑整。

大地坐标或厂区坐标离原点很远时，可扣除稳定偏移在局部场景工作，保存反向映射。检查时用原始数值基准与实际模型世界坐标比较，避免先把双方量化到相同精度再得到虚假的零误差。数值复现误差不代表现场测量精度。

尺度先于细节：灰模阶段核对总体长宽高、接口和一件已知尺寸的对照物。不能等总装结束后靠目测逐件调大调小。

## 3. 区分组件类型、实例与空间分配

先建组件目录，再决定按什么粒度建模或委派：厂房/建筑模块、加工设备、工位/夹具、工件/载具、物流设备、仓储、辅助设施等按当前图纸实际内容选择，不固定要求所有类别。

- **类型/变体**：可独立理解、复用和替换的资产。型号、结构、运动或接口不同才拆变体；仅摆放位置不同不重做资产。
- **实例**：某个类型/版本在总图中的一处放置，具有稳定实例 ID、位置、朝向和来源。
- **分配区/符号**：只证明空间或示意数量；真实设备数未知时保留未知。示例车、示例工件或建议设备需单独标记，不混入图纸确定数量。

每类组件按 [组件任务与交付合同](component-job-contract.md) 领取任务。目录至少能追溯：组件 ID、功能、参考状态、主尺寸证据、预计实例、接口、负责代理、交付版本及哪些内容待确认。

## 4. 每类组件完整执行建模流程

一次整厂参考搜索不能替代逐组件搜索。不要只派一个代理画整厂，再让其他代理增加装饰物。

1. **资料与参考检索**：先读用户资料和现有资产；按具体型号查制造商安装/外形图、手册、合法 CAD 和实物多视角。记录实际检索过的来源、可用视角、尺寸和未找到的内容。已有资料充分且适配时注明复用，不为形式重复联网或下载；未指定型号且资料不足时也应按设备类型找结构参考。
2. **选择复原或通用方案**：无法确认指定外形时，按设备功能选通用结构并注明哪些来自同类参考、哪些是设计值。根据资料缺口、任务精度与可获得来源判断何时停止检索，记录原因；不无限搜索，也不在尝试之前声称“找不到”。
3. **结构与安装基准**：先确定局部坐标、主参数、固定/活动边界、接地支承、装卸方向、接口及需要的包络。不能把同一白色箱体稍改尺寸就当作所有机床类型：通用车床仍需可信的床身/主轴/刀架关系，龙门类需门架/工作台/加工空间关系；具体细节以用途和参考决定。
4. **灰模与轮廓核对**：在局部原点按统一尺度建灰模，以匹配参考的视角及背面、顶部检查形状、非对称性、主要开口和接口。通过后补功能结构、材质与必要细节。
5. **组件自检与交付**：执行主 skill 的层级、几何、材质、姿态与导出检查。按合同交付可编辑源、必要交换文件、实际看过的多视角图、尺寸/接口和未验证项。不能用总装远景代替单组件视觉审查。

参考仍不足但用户已允许通用模型时，在统一参数范围内推进。缺失信息会改变设备功能类别、占地、接口或装配可行性时，集中说明冲突并继续不依赖该信息的任务；不逐件重新索取已经给过的授权。

对于外观示意可使用简化孔位或贴花，但需标明；影响轮廓、装配、通行、夹持或交互的孔、开口和接口要有相应几何，不能用深色面假装通孔。

## 5. 可以并行的工作与必须串行的写入

按**组件类型或有实质差异的变体**委派，重复实例由总装复用。主代理维护尺度/坐标/风格合同、组件目录和最终装配；组件代理完成自己那一类的完整流程，而非只输出建模建议。

同一 Blender MCP 通常连接同一实时进程，共享活动场景、选择、数据块和文件路径。多个输出文件名不意味着运行环境已隔离。

| 现场条件 | 可行分工 |
|---|---|
| 只有一个实时 Blender | 参考检索、参数、脚本与报告可并行；所有实时 MCP 写入由主代理排队执行。组件代理可提交脚本/检查项，由主代理执行和回传结果，代理继续完成审查 |
| 有可用的独立后台进程 | 每个组件独立文件和工作目录，从干净启动建模、渲染与回读；不打开或覆盖 GUI 正在编辑的同一文件 |
| 有多个实时实例且工具能明确路由 | 先核实各调用确实落在不同实例，再分配写入；不假定相同工具名或另开窗口已实现隔离 |

每个组件独占自己的源文件、交换文件、构造脚本与预览目录。共享风格合同由主代理管理；不让并行代理改写同一总装、材质库或共同脚本。变更单位、接口或组件包络时，先同步合同及受影响任务，禁止代理各自“修正比例”。

## 6. 组件验收后装配，不在总装中重造资产

总图可以先用占位灰模检查范围；正式集成使用已完成组件自检的版本。仅完成灰模的组件继续标为灰模，不因已经放入厂房而升级为完成。

- 组件源保留本地安装原点；实例只记录摆放变换和明确的单位转换。需要变体时修改参数再生成，避免非均匀缩放破坏孔、圆轴、门与接口。
- 实际层级按功能表达，例如“工厂 → 作业区 → 装配岛 → 设备/工位 → 固定与活动件”。不强制每一层都加 Empty；能由有意义的 Mesh 承载的节点直接承载。导出后仍需保留语义，不能只依赖不被交换格式保留的 Collection 分组。
- 重复资产尽量共享已验证的 Mesh/材质，个别活动件的变换和实例属性可独立。检查导出器是否保留复用；不要只因 Blender 文件较小就宣称运行时已优化。
- 以接口匹配安装面、前后方向、装卸朝向、轨道端点和高度；位置与旋转均需验证。找不到准确安装点时，区域中心放置只属于建议/示例。
- 实体模型、功能区标线、AGV 路线注记、文字和参考线分开管理。路线绘出来不表示已经实现导航图、交通可行性或调度仿真。

## 7. 总装空间核对与回修

| 层面 | 要实际核对的关系 |
|---|---|
| 来源与尺度 | 轮廓/实例的来源标识、位置和朝向、反向坐标映射、主尺寸、来源数量与示例数量分开 |
| 安装关系 | 接地与支承、安装面贴合、模块对接、夹具/工件接口与高度，不悬空、不靠拉伸凑合 |
| 运行空间 | 本体包络、门/抽屉/机械臂等运动包络、装卸与检修包络；净距要求取用户/OEM 等已给依据，未知则记录待定 |
| 层级与复用 | 装配岛整体移动、组件单独替换、运动下游跟随且其他分支不动、实例版本与资产原点保持 |
| 几何与显示 | 单组件及总装求值网格、重复放置/面、薄细节倒角退化、法线、开放标线的合理例外、共面闪烁 |
| 交换交付 | 独立组件与总装按范围导出；优先在干净进程回读尺寸、轴向、安装基准、活动节点、材质和依赖；后台不可用时可在隔离独立场景回读并记录隔离方式与局限，不把它等同跨环境验证 |

包围盒包含/重叠用于初筛，不是精确碰撞结论。静态无穿插、若干姿态无碰撞和连续全行程无碰撞分别记录。开门不能只确认门节点动了，还需看门与控制面板、邻机和通道的关系；层级随动检查不能替代净空检查。

用同一坐标/相机做原图与模型投影对照，另看总体斜视及关键接口近景。发现差异时回到源头：全体偏差检查单位/坐标，单类型比例错误回组件，个别实例偏差改摆放，原图缺边或标签矛盾保留推导依据。不要把所有问题都通过移动或缩放实例掩盖。

检查深度与交付用途匹配；碰撞方法、目标引擎或来源能力未覆盖的内容明确标“未检查”。性能敏感任务记录实例化后的场景开销与目标环境表现，不能用孤立资产检查替代整厂性能实测。

## 8. 交付与完成边界

根据任务交付原图预览、分类/实例及估算清单、组件库、可编辑总装、必要交换格式、关键视图与核对记录。原点版本的组件可以在数据上重叠，另提供分开陈列的组件审查视图；不能让用户只看到重叠的“资产库”。

分开报告组件造型审查、网格检查、总装位置核对、运动/净空检查、导出回读与目标引擎实测。只有通用方案和已确认的原图部分完成时，准确称为当前精度下的交付，不称指定型号复原或现场验收。

独立新场景仍可能保存在旧 `.blend` 中。最终核对保存文件的依赖范围和路径，避免把无关旧项目一并写入工厂文件；能够在 GUI 显示交付时也核对当前活动文件路径。MCP 断开则报告保存与 GUI 展示的实际状态，不把“文件已生成”写成“已在用户 Blender 打开”。

CAD 装配、工厂资产与公开 skills 的采用范围见 [来源与取舍](sources.md)。

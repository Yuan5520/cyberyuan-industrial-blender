# 工厂组件任务与交付合同

用于主代理与组件代理约定输入、文件所有权、组件制作责任和总装接口。可以用 JSON、表格或结构化任务说明，不要求为小任务建立数据库。以下字段按用途填写；未知信息保留未知，不用示例值冒充来源事实。

## 主代理发出组件任务

一个任务通常对应一个可复用类型或真实变体，而非某台设备的一个螺栓或全部同型实例。

| 输入 | 合同应包含的内容 |
|---|---|
| 标识与范围 | 组件 ID/版本、功能类型、是否指定型号、哪些附件属于本组件、是否只做灰模 |
| 全局基准版本 | 物理单位与 Blender 换算、项目坐标约定、统一材质/细节约定；引用主代理维护的同一版本 |
| 局部安装基准 | 组件原点、前方/上轴、接地面、需要的连接点与接口朝向 |
| 证据与尺寸 | 用户资料、CAD handle/图层/区域、已有资产；每个主尺寸的值、单位、来源与已知/估算/未知状态 |
| 包络含义 | 设备本体、附件、操作/运动、检修包络分别记录；CAD 分配区不自动成为设备尺寸 |
| 运动与复用 | 需独立的门/轴/载台、随动关系、设计行程及依据；预计重复使用情况 |
| 执行环境 | 实时写入负责人，或已验证隔离的后台实例；独占目录与源文件，允许读取的共享资源 |
| 交付与核对 | 用途、观察距离、源文件与所需交换格式、关键视角、接口检查和明确未要求的工作 |

### 可直接改写的委派说明

> 负责本任务指定的组件类型，按统一尺度和局部安装基准完成：读取用户参考与已有资产 → 独立检索该组件的参考图/尺寸/结构 → 判断指定复原或通用方案并记录估算 → 灰模与多视角核对 → 功能结构、固定/运动层级、材质 → 几何与代表性姿态检查 → 保存、按要求导出和回读。重复实例由总装代理生成。不要自行修改全局比例、总装位置、共同材质库或别的组件。只有一个实时 Blender 时，不自行并发写该实例；提交待执行脚本并根据主代理回传结果继续审查。找不到指定资料时，记录实际查过的来源和缺口，按已授权的通用方案推进。包络或接口发生冲突时报告，不靠非均匀缩放凑合。

主代理须把实际组件 ID、目录、基准版本和现有授权一起发出；不只发送“帮我建一个机柜”。组件代理阅读主 skill 以及相关单组件参考，不能只凭此委派说明跳过完整流程。

## 组件代理交回什么

交回一个可安装、可替换的组件，以及能判断其可用范围的证据。建议记录：

```json
{
  "component_id": "example_machining_unit",
  "asset_revision": "r1",
  "global_contract_revision": "r1",
  "model_basis": "generic",
  "reference_search": {
    "status": "not_started",
    "queries": [],
    "checked_sources": [],
    "used_reference_ids": [],
    "missing_information": [],
    "stop_reason": null
  },
  "units": {
    "authoring_unit": "m",
    "meters_per_blender_unit": 1.0
  },
  "installation": {
    "origin_definition": null,
    "local_forward": null,
    "local_up": null,
    "ground_plane_local": null,
    "interfaces": []
  },
  "dimensions": {
    "model_envelope_m": null,
    "body_dimension_evidence": [],
    "operating_envelope": null,
    "service_envelope": null
  },
  "motion_nodes": [],
  "files": {
    "editable_source": null,
    "exchange_files": [],
    "reviewed_views": [],
    "reports": []
  },
  "checks": {
    "reference_fidelity": "not_checked",
    "mesh_geometry": "not_checked",
    "visual_review": "not_checked",
    "motion_follow": "not_checked",
    "clearance": "not_checked",
    "export_roundtrip": "not_checked",
    "target_engine": "not_checked"
  },
  "unresolved_items": [],
  "ready_for_assembly": false
}
```

这是未完成任务的示例，不是通过报告。实际交付时逐项写入证据；不适用、已检查、发现问题、已解释例外和未检查分别记录，不统一改成 `passed`。`ready_for_assembly` 依据当前任务必需项判定，只代表当前用途和精度下可集成，不能推出全部检查完成。未要求的目标引擎实测可保留未检查，不自行扩展任务；未解决的单位、原点、必需接口或几何错误则不能强行放行。

- `checked_sources` 记录实际读取的链接/本地参考、型号/图号、尺寸单位、可见结构及资产许可；不只堆搜索结果链接。
- `body_dimension_evidence` 逐尺寸注明原图/官方资料/同类估算/为用途设计。模型实测包络与真实设备尺寸的证据分开。
- `interfaces` 记录名称、局部位置、朝向和适配对象；`motion_nodes` 记录稳定路径、类型、局部轴、带单位的行程/角度及来源。
- 组件源位于本地安装基准；陈列图位置不写回安装源。附件和纹理依赖采用可移植组织。
- 未完成的视觉审查、净空或回读不得写成完成；代理脚本正常结束也不能单独证明资产可用。

## 主代理保留的总装实例记录

每个实例记录 `instance_id`、引用的 `component_id` 与 `asset_revision`、`global_contract_revision`、来源对象/区域、位置、旋转、明确的单位转换、装配组及放置依据。示例放置须有独立标识，来源数量也保留来源类别。

组件合同不保存某个实例的永久厂区偏移；总装实例不另存一套未经同步的组件尺寸。版本更新时复核包络和接口，再更新受影响实例。

## 集成时的快速核对

1. 基准版本、单位和安装原点一致，组件类型与来源解释匹配。
2. 导入实测尺寸符合合同，旋转后前方、安装面和接口方向正确；不凭截图看起来大小相近放行。
3. 资产文件与审阅视图可打开，主结构及活动件完整；泛化部分与指定产品区分清楚。
4. 摆放符合安装点/接口或明确标为建议放置。必要运动与检修空间尚未知时保留未确认状态。
5. 总装层级仍可整体移动装配组、单独替换组件；导出回读后活动节点和材料依赖保持。

不满足合同的组件回到其负责代理修正；其余独立组件继续推进。不要为保持总装截图好看而掩盖错误比例、缺失接口或未完成状态。

# Blender MCP 操作与可恢复建模

## 启动与范围

使用当前会话实际提供的 Blender 工具，不把某个 MCP 实现的命名、端口、版本或工具集合写死为必要条件。

当前常见能力映射：

| 目的 | 工具能力 |
|---|---|
| 版本、插件与可用集成 | `get_addon_status` 或等价工具 |
| 当前文件、单位、对象及层级 | `get_scene_info` |
| 程序建模与详细检查 | `execute_blender_code` |
| 多视角、线框、材质反馈 | `look` 或截图/渲染工具 |

先读工具说明，再读状态。若工具要求 `user_prompt`，传用户原话；不把助手自己的计划伪装成用户指令。只查询当前任务所需范围。

连接失败时保留现状，说明具体失败；已安装 Blender 可在隔离后台环境工作，但不能把后台检查描述为实时 MCP 工作已验证。不自动重启用户 Blender、安装插件、修改遥测/偏好或重配 MCP。

## 修改前

确定 `.blend` 路径、是否有未保存修改、当前集合和任务对象。保留必要的版本副本；新任务使用独立集合或文件，禁止无条件删除全场景。

保存用户原始文件需符合当前授权；不要覆盖不属于任务的文件。两个进程不能同时写同一 `.blend`。重试前读取实际状态，确认上一段是否部分成功。

工厂组件可并行做资料与隔离文件任务，但共享实时 MCP 的场景写入应排队；具体分工见 [工厂级流程](factory-workflow.md)。独立 Scene 不等于独立文件，导出/保存前核对实际 `.blend` 路径及依赖范围，避免带入无关旧场景。

## 分段执行

每段完成一个可检查的目标，例如灰模、一个功能组件、层级整理、材质、导出副本。输出精简 JSON：修改对象、尺寸、层级、异常及文件路径。

- 优先使用 data API、`bmesh` 和确定的对象引用。使用 `bpy.ops` 时明确 active object、选择集、模式和上下文；完成后恢复不属于任务的操作状态。
- 每次调用按独立 Python 命名空间编写，显式 import，并通过稳定名称/ID 找数据，不依赖上一段局部变量。
- 创建/更新尽量可重复执行；不要每次调用都无条件新增 `.001` 对象。记录本任务拥有的数据，清理仅限其范围。
- 不硬编码可能变动的枚举或已删除 API；探测当前 Blender 版本、RNA 属性与算子可用性，针对实际环境使用代码。动态枚举在 RNA 中为空时，检查算子的动态选项来源、插件实现或可用调用，不仅凭空列表认定格式不受支持，也不因此自动升级插件。
- Shader 节点按类型找，例如 `node.type == 'BSDF_PRINCIPLED'`；材质实际颜色设置在 shader 输入，viewport 颜色并不代表渲染颜色。
- 用户模型库优先复用合适资产；导入后核查尺寸、变换、原点、拓扑和许可。不能因文件名像某型号就认定比例和运动轴正确。

## 观察—修改—观察

灰模后和最终交付前必须实际查看图片。结构阶段以 solid/灰模和匹配参考的视角为主；检查拓扑用 wireframe，内部用 xray，材质用适当材质/渲染视图。

选择当前最大的不一致，改其结构原因，再用相同视角复查。不通过裁切、镜头或灯光让缺陷躲出画面。图片已生成但未被打开审阅，不能记录为视觉验收。

长任务按阶段保存、简要汇报。发生异常先局部诊断，不盲目重跑完整场景生成脚本。

## 隔离检查

只读脚本可在 MCP 中调用，不修改当前场景：

```python
import json, runpy
api = runpy.run_path('/absolute/installed/skill/scripts/audit_asset.py')
report = api['audit_asset']('AssetRoot')
print(json.dumps(report, ensure_ascii=False))
```

示例路径必须替换为实际安装路径，根名称替换为任务对象。该脚本只创建临时求值网格并释放，不调用保存、删改或自动修复操作。

独立文件检查可用 Blender 后台进程：

```sh
"$BLENDER_EXE" --background --factory-startup --disable-autoexec "$ASSET_BLEND" --python-exit-code 1 \
  --python "$SKILL_DIR/scripts/audit_asset.py" -- \
  --root AssetRoot --out "$REPORT_PATH"
```

变量用实际路径赋值。独立检查默认不加载个人启动配置，也不自动运行输入文件携带的脚本；确需第三方修改器时单独核查依赖。不要将项目目录用作 skill 自测输出目录。`scripts/self_test.py` 仅允许在全新后台实例运行，见测试场景文件。
